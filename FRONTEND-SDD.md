Цель интерфейса

Маркетолог должен видеть, в какой кампании и каком потоке он работает, куда идёт посетитель и как распределяется трафик внутри выбранного потока. Два экрана, русские подписи, Jinja2, HTML, CSS и JavaScript. Запросы браузера направляются к /api на том же сервере. Контракт запросов и ответов определён в BACKEND-SDD.md.

Экран «Создать кампанию»

Поля «Название кампании», «Страна» и «Оффер». В стране искать по коду или названию, выбирать одно значение. Оффер искать по ID и названию; результат «3749 · Кофемашина» сохраняет ID. Введённый поисковый текст сам по себе оффер не выбирает.

Под полями показать будущий маршрут простыми словами. Для AU: «Австралия → Google» и «Все остальные → Кофемашина (3749)». Незаданные значения отображать как «Выберите страну/оффер».

«Создать кампанию» активно для заполненной валидной формы. При изменении данных после завершения операции начать новый запрос с новым ключом. Для одного нажатия, повторной отправки после сетевого сбоя и восстановления той же попытки использовать один Idempotency-Key; хранить ключ и отпечаток ввода в sessionStorage. В ожидании показывать «Создаём…».

Успех открывает страницу созданной кампании. При отказе сохранить ввод и показать сообщение рядом с полем либо кнопкой. При частичном результате вывести номер операции и ID кампании, если известен; действие «Проверить и продолжить» повторяет исходный запрос с его ключом.

Экран «Редактор кампании»

Дать поиск по названию/ID и возможность открыть конкретный ID. Адрес страницы вида /campaigns/125/edit пригоден для обновления и закладки. В заголовке название и ID. Под ним — домен, группа, источник и режим ротации. Затем вертикальный список потоков.

Вертикальные карточки удобнее для этого задания: маркетолог читает условия сверху вниз и сразу видит список офферов рядом с потоком, на который повлияет кнопка. Свободное перемещение блоков мышью подразумевало бы изменение порядка и добавило бы действие, которого в ТЗ нет.

Для существующей кампании читать типы, состояние и правила с сервера. При необходимости группировать по приоритету forced, regular, default; учитывать position внутри группы. При ротации по весу показать режим и веса обычных потоков: визуальный порядок карточек в этой группе не обещает последовательный обход. Отключённый поток подписать «Выключен». Если есть другие фильтры, показать их фактическое описание; подпись «Остальные посетители» использовать только для соответствующего маршрута. Незнакомые схемы отображать по данным сервера с понятной подписью. Номер карточки или её имя не служит признаком доступности редактора. Основание — порядок обработки потоков.

Это пример сохранённой конфигурации. Процент — настройка распределения внутри этого потока. Подпись должна отличать эти данные от кликов и от веса самого потока. Для штатной активной схемы показать сумму сохранённых долей. В режиме только чтения для неизвестной схемы или отключённых связей показать исходные значения без нормализации. Длинные названия переносить. В узком окне каждую строку можно сделать компактной карточкой, сохранив число, знак процента и действие.

Редактирование

Нажатие «Добавить оффер» открывает поиск прямо в нужной карточке. Результаты с уже добавленными ID пометить «Уже в потоке». Выбор результата и кнопка «Добавить» отправляют один запрос, включая текущую revision.

«Убрать из потока» относится только к одной строке. Текст действия называет его область. По временному правилу для единственного активного оффера действие недоступно с видимым пояснением. При просмотре видео сверить это поведение и момент сохранения.

На время записи заблокировать повторные изменения этой карточки, показать «Сохраняем…». При успехе заменить данные ответом бэкенда. Рядом с добавленным/удалённым оффером обновить все доли, которые изменились. Самостоятельный расчёт процентов в JavaScript не требуется.

При 409 показать «Поток изменился. Обновите данные» и кнопку «Обновить». При тайм-ауте — «Проверить состояние» с повторным чтением. До подтверждения показывать последнее прочитанное состояние с сообщением об ошибке. При переключении кампании игнорировать поздний ответ для прежнего экрана.

Состояния поиска: ввод, загрузка, список, пустой результат, ошибка с повтором. Игнорировать устаревшие результаты быстрых последовательных запросов. Выбор доступен мышью и клавиатурой, включая Enter и Escape. Фокус после изменения возвращать к следующему осмысленному действию той же карточки. Ошибки и успехи передавать текстом.

Приёмка интерфейса

Открыть кампанию по прямому URL и обновить страницу. Проверить режимы одного и нескольких потоков с офферами, отсутствие потоков, редирект без офферов и выключенную связь. Добавить и убрать оффер при одинаковых названиях и разных ID. Проверить две вкладки со старой revision. Вызвать ошибку сервера и убедиться, что интерфейс не сообщил об успехе. Сравнить каждое изменение долей с правилами в BACKEND-SDD.md и видео, когда оно доступно. Пройти основную форму клавиатурой и на ширине 375 px. Приёмку закончить сравнением результата в панели и в админке Keitaro.
