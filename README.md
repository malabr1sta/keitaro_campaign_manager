# Keitaro Campaign Manager

Веб-приложение для создания кампании с двумя потоками и изменения набора офферов
существующей кампании Keitaro. Интерфейс на русском: FastAPI, Jinja2 и обычный
JavaScript без сборки фронтенда. Python 3.12, uv, SQLAlchemy, SQLite, Alembic.

Keitaro хранит конфигурацию и обрабатывает рекламные переходы. Локальная БД хранит
только журнал операций создания. Браузер обращается к `/api` приложения; API-ключ
Keitaro остаётся на сервере.

## Быстрый запуск: Docker Compose Watch

Нужны Docker Engine и Docker Compose с поддержкой `develop.watch` и команды `watch` (проверено на 2.24.6).

```bash
cp .env.example .env
# Заполните KEITARO_BASE_URL и API_KEY в .env

docker compose watch
```

Откройте <http://localhost:8000>. При старте контейнер выполняет
`alembic upgrade head`, затем запускает один процесс Uvicorn. Проверка `/health`
подтверждает доступность локальной таблицы операций, но не доступ к Keitaro.

Watch синхронизирует `app/`, `migrations/` и `alembic.ini` с перезапуском процесса.
Изменения `pyproject.toml`, `uv.lock` и Dockerfile вызывают пересборку. Изменив
зависимости, обновите lock-файл через `uv lock`. После изменения `.env` выполните
`docker compose up -d --force-recreate`, затем снова `docker compose watch`.

SQLite находится в `/app/data/app.db`, данные сохраняются в volume `app-data`.
`docker compose down` сохраняет БД; `docker compose down -v` удаляет её вместе
с журналом восстановления операций — не используйте эту команду для обычного перезапуска.

```bash
docker compose logs -f app
docker compose exec app alembic current
docker compose exec app alembic upgrade head
docker compose down
```

Режим без Watch и без зависимостей разработки:

```bash
docker compose -f compose.yaml -f compose.production.yaml up -d --build
```

Порт по умолчанию доступен только на `127.0.0.1`. Приложение рассчитано на доверенное
локальное использование: собственного входа пользователей нет. Для доступа из сети
нужны аутентификация на reverse proxy и TLS. Один worker и один экземпляр приложения
обязательны: блокировки операций и потоков находятся в памяти процесса.

## Подключение к Keitaro

```dotenv
KEITARO_BASE_URL=https://tracker.example.com
API_KEY=your-api-key
DATABASE_URL=sqlite:///./data/app.db
```

`KEITARO_BASE_URL` — адрес установки без `/admin/` и `/admin_api/v1`, например адрес
до `/admin/#!/campaigns` в браузере. API-ключ получите в профиле пользователя Keitaro;
доступ зависит от прав и редакции трекера. Посетительский домен кампании может отличаться.

В форме выбираются **существующие** домен, группа кампаний и источник трафика,
полученные через API. Необязательные значения по умолчанию:

```dotenv
KEITARO_DOMAIN_ID=1
KEITARO_GROUP_ID=2
KEITARO_TRAFFIC_SOURCE_ID=3
```

Если справочники пусты, создайте записи в админке Keitaro. Приложение их не создаёт
и не настраивает DNS. Не коммитьте `.env` и реальные ответы с секретами. `.env` также
исключён из Docker build context. Имена переменных и примеры есть в `.env.example`.

## Локальная разработка с uv

Установите uv и Python 3.12, затем:

```bash
uv sync --frozen
cp .env.example .env  # только если собственного .env ещё нет
# Настройте .env
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

`uv.lock` фиксирует зависимости. Для намеренного обновления используйте `uv lock --upgrade`
и повторите тесты. Конфигурация окружения имеет приоритет над `.env`.

### Миграции

```bash
uv run alembic current
uv run alembic upgrade head
uv run alembic revision --autogenerate -m "describe change"
uv run alembic check
```

Первая миграция создаёт `creation_operations` с уникальными `request_key` и `alias`.
При изменении моделей просмотрите сгенерированную миграцию перед применением.
`alembic downgrade base` удалит таблицу журнала — это допустимо только для одноразовой
тестовой БД. Для резервной копии SQLite остановите приложение и скопируйте файл БД
или используйте штатный SQLite backup API.

## Основные сценарии

1. Откройте главную страницу, введите «Кофемашина — ноябрь».
2. Найдите AU / Австралия и выберите результат. Аналогично выберите существующий
   оффер A по ID или названию. Поисковый текст без выбора не является оффером.
3. Выберите домен, группу и источник. Нажмите «Создать кампанию».
4. После подтверждения откроется `/campaigns/{id}/edit`. Первый поток направляет AU
   на `https://www.google.com/`; второй без фильтров использует A с долей 100%.
5. В карточке офферов добавьте B: ожидаются 50/50. Уберите A: B получает 100%.
   Оффер A остаётся в общем каталоге. Обновите страницу и сравните с админкой Keitaro.
6. Откройте вручную созданную кампанию через поиск или прямой ID и повторите изменение.

Стрелки, Enter и Escape управляют поисковыми подсказками. Потоки группируются по
`forced`, `regular`, `default`, затем по позиции. При весовой ротации отображаются
веса; порядок карточек не обещает последовательный обход. Незнакомые схемы и потоки
с выключенными связями доступны для чтения.

### Доли и конфликты

До получения видео действует **временная политика**: при изменении состава 100 делится
поровну между активными офферами, остаток распределяется в сохранённом порядке.
Примеры: 50/50, 34/33/33; при удалении из 70/20/10 два оставшихся получают 50/50.
Простое открытие 70/30 сохраняет исходные значения. Последний активный оффер нельзя убрать.
Это проектные решения, а не ограничения Keitaro, и совпадение с видео не подтверждено.

Каждое изменение содержит revision. Если другая вкладка успела сохранить поток,
сервер возвращает 409. Нажмите «Обновить». При тайм-ауте сервер сначала перечитывает
поток; если запись не подтверждена, интерфейс предлагает «Проверить состояние».
Без условной записи на стороне Keitaro полностью исключить вмешательство внешнего
редактора между GET и PUT невозможно.

### Восстановление создания

Ключ попытки и её данные сохраняются в `sessionStorage`, сервер сохраняет шаги и
полученные ID в SQLite. Повторный завершённый запрос возвращает прежний результат;
тот же ключ с другими данными даёт 409. При частичном результате форма сохраняет
исходные данные и предлагает «Проверить и продолжить».

После потери ответа приложение ищет кампанию по стабильному alias, поток — по
уникальному имени в известной кампании. Если найден ровно один результат, проверяет
конфигурацию и продолжает. Если результат отсутствует либо неоднозначен, новый POST
не выполняется: необходима ручная проверка в админке. Сохраните ID операции из ошибки.
Не очищайте журнал, не меняйте ключ и не начинайте новую попытку вслепую.

Кампания создаётся выключенной, включается после проверки обоих потоков и снова
перечитывается. Совместимость этой последовательности с реальным стендом пока не подтверждена.

## Тесты и проверки

Обычный набор не обращается к реальному Keitaro и не требует `.env` с секретами:

```bash
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
```

Браузерные сценарии запускаются отдельно в Chromium:

```bash
uv sync --frozen --group browser
uv run --group browser playwright install chromium
# В чистом Linux runner могут понадобиться системные зависимости:
# uv run --group browser playwright install --with-deps chromium
RUN_BROWSER_TESTS=1 uv run --group browser pytest tests/browser -q
```

Браузер обращается к приложению через тестовый HTTP-мост Playwright → TestClient.
Реальные исходящие запросы Keitaro заменены `httpx.MockTransport`. Это проверяет
HTML/JS, маршруты и сервис вместе, но не сеть, reverse proxy и живой трекер.

Проверяются: распределение долей, выбор AU/GE на синтетической конфигурации, повторы,
потеря ответа при создании кампании и обоих потоков, неоднозначный исход, ревизии,
сохранность соседнего потока и лендингов, удаление только связи, ошибки API без ключа
в ответе, миграции upgrade/downgrade, мобильная форма и клавиатура, две вкладки.
CI запускает линтер, форматирование, тесты, браузерные сценарии и Docker build.

Фактически пройдено локально: **29 тестов API/сервиса/миграций и 3 браузерных
сценария** в Chromium. Проверены Ruff, синтаксис JavaScript, `alembic check`,
`docker compose config --quiet` и запуск Uvicorn (главная страница и `/health`: HTTP 200).
Chromium потребовал запуска вне ограниченной песочницы. Внешние библиотеки тестового
клиента и pytest выводят предупреждения об устаревающем API; тесты проходят.

## Статус интеграции и ограничения

**18 ноября 2026:** адрес и ключ из локального `.env` прочитаны; GET к API получил
Cloudflare HTTP 403 / Error 1010 (`browser_signature_banned`). Сам ключ не удалось
проверить. Записи в предоставленном Keitaro не выполнялись, версия установки неизвестна.
Владельцу домена нужно разрешить обращения серверного клиента к Admin API.

Фикстура `tests/conftest.py` синтетическая, не снята со стенда. До живой приёмки
необходимо сверить в профиле установки её Admin API Reference и DevTools:

- создание кампании: `name`, `alias`, `type=position`, `state`, `domain_id`,
  строковый `group_id`, `traffic_source_id`;
- потоки: `schema=redirect` / `landings`, `action_type=http`, `action_payload`,
  фильтр `{name: country, mode: accept, payload: [AU]}`, позиции и состояния;
- `PUT /campaigns/{id}` для включения и частичный `PUT /streams/{id}` с `offers`;
- полноту выдачи каталогов, форматы состояний и возможную пагинацию версии установки.

Адаптер версии сосредоточен в `app/keitaro_client.py` и построении/нормализации данных
в `app/campaign_service.py`. Неизвестный контракт не считается подтверждённой интеграцией.
После снятия блокировки сохраните обезличенные образцы, проверьте симулятором Keitaro
AU и GE, редактирование ручной кампании и сохранность полей при PUT.

Видео работодателя не предоставлено. Нужно сверить четыре примера: добавление второго,
третьего, удаление из неравномерного распределения и последнего активного оффера.

Проверено на Docker Engine 29.1.3 и Compose 2.24.6: `docker compose watch`
собрал образ, применил миграции, запустил контейнер со статусом `healthy`; `/` и
`/health` вернули HTTP 200. Изменение CSS было перенесено в контейнер через Watch,
после чего контейнер перезапустился и снова стал `healthy`.

## Структура

- `app/routes.py` — HTML и JSON API, валидация.
- `app/campaign_service.py` — создание, восстановление, чтение и изменение кампаний.
- `app/keitaro_client.py` — HTTP-транспорт и безопасные ошибки зависимости.
- `app/policy.py` — revision и временная политика долей.
- `app/models.py`, `app/db.py`, `migrations/` — локальный журнал и миграции.
- `app/templates/`, `app/static/` — интерфейс без npm-сборки.
- `tests/` — сервисные, транспортные, миграционные и браузерные проверки.

Контракты исходного задания: `CODEX-BRIEF.md`, `BACKEND-SDD.md`, `FRONTEND-SDD.md`.
Расширения реализации: API `/api/configuration`, `/api/countries`, `/health` и
необязательные `domain_id`, `group_id`, `traffic_source_id` в POST `/api/campaigns`
для выбора справочников из формы. Если ID не переданы, используются настройки окружения.
