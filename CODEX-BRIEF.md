Keitaro Wrapper · задание для Codex

Цель и контекст

За пять дней подготовить проверяемое веб-приложение для маркетолога. Маркетолог создаёт кампанию в уже установленном Keitaro за одно нажатие и может изменить набор офферов существующей кампании. Посетитель рекламной ссылки взаимодействует напрямую с Keitaro. Подсчёт кликов, определение страны и перенаправление выполняет трекер. Результат работы — репозиторий для GitHub, README по миграциям, настройке и запуску. Адрес и ключ рабочего стенда передаются отдельно.

Прочитай этот файл, BACKEND-SDD.md и FRONTEND-SDD.md. Сначала изучи существующий репозиторий. Реализуй оба сценария, проверь их и опиши результат. Новому репозиторию подойдут Python, FastAPI, SQLAlchemy, Alembic, SQLite, httpx, Jinja2 и небольшой обычный JavaScript. Достаточно одного приложения и одного процесса для проверочного запуска.

Что обязательно по ТЗ

Форма принимает название, код страны и существующий ID оффера. Макет показывает поиск оффера с подсказками.

У новой кампании настроены домен, группа кампаний и источник трафика. Поток с геофильтром направляет посетителей выбранной страны на Google. Для остальных работает поток с выбранным оффером.

Редактор читает кампанию из Keitaro, в том числе созданную вручную. В пределах выбранного потока можно добавлять и убирать офферы. Изменения видны после обновления страницы и в админке трекера.

Поведение кнопок и цифры должны соответствовать видео работодателя «Mikhail Novikov — keitaro wrapper - test». В переданных материалах есть скриншот ссылки и пример 50/50. Доступного URL или записи для просмотра не было.

Принятые проектные решения

Одна страна на новую кампанию согласно формулировке ТЗ. Доменные настройки задаются администратором через окружение. Название и ID вместе помогают различить одноимённые офферы. Для схемы потоков использовать вертикальные карточки, внутри нужной карточки — редактор офферов. Keitaro хранит кампании, локальная БД — операции создания и их исходы. Отдельные микросервисы и сборка фронтенда для этого объёма не нужны.

Зафиксировать, когда отправляется изменение, какие именно цифры и столбцы показывает интерфейс, как трактуются выключенные офферы. Внести наблюдения в спецификацию и тесты. Пока видео недоступно, продолжать разработку с явно обозначенным временным правилом из BACKEND-SDD.md. Документировать расхождения и не выдавать этот режим за проверенное совпадение.

Чем проверить

1

Получить параметры тестового стенда, изучить видео при наличии. Сделать клиент, одну миграцию и вертикальный срез чтения. Снять обезличенные образцы ответов и тел запросов.

В браузере открывается существующая кампания. Видны ID, позиции потоков, активность, офферы и сохранённые доли. Без доступа аналогичный тест проходит на фикстуре, интеграция отмечена как непроверенная.

2

Реализовать создание кампании и двух потоков, журнал шагов, обработку повтора.

В админке видны нужные домен, группа и источник. В симуляции Keitaro выбранная страна попадает на Google, другая — на выбранный оффер.

3

Реализовать изменение состава офферов, политику долей, защиту от устаревшей формы.

Добавление и удаление применяются к одному потоку. Доли совпадают с эталонными примерами, остальные настройки сохраняются.

4

Завершить формы, карточки, ошибки, клавиатурное управление и проверку в двух вкладках.

После перезагрузки и в новой вкладке видны подтверждённые сервером значения. Ошибка обновления не выглядит как успешная запись.

5

Проверить установку из чистого клона, миграции и оба сценария. Подготовить README и результаты проверки.

По README другой разработчик запускает приложение, настраивает стенд и воспроизводит проверку.

Приёмочный пример

Создать «Кофемашина — ноябрь», страна AU, существующий оффер A. Открыть созданную кампанию в админке. Проверить назначения для AU и GE. В редакторе добавить существующий оффер B. После чтения из трекера увидеть A и B с ожидаемыми долями. Убрать A из потока. B получает весь трафик этого потока по временной политике. A по-прежнему доступен в общем каталоге. Первый поток всё ещё отправляет AU на Google. Повторить редактирование на отдельной кампании, заранее созданной через админку.
